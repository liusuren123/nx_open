# Nx Optx 媒体嗅探器（Chrome 扩展）

嗅探当前网页上的媒体流，在**页面右下角**弹出提示卡片，点一下就能把流加到正在运行的
**Nx Optx 播放器**里（通过 `nxoptx://` 协议，见 `../src/nx/vms/client/desktop/nxoptx/README.md`）。

## 安装

两种方式，任选一种（Chrome 的「加载已解压的扩展程序」需要一个**文件夹**）：

**A. 从 zip 安装（推荐）**

1. 解压 `nxoptx-chrome-extension.zip` 到一个**长期保留**的目录，例如
   `D:\tools\nxoptx-chrome-extension`（Chrome 会记住这个路径，别放在会被清理的地方）；
2. 打开 `chrome://extensions/`，右上角打开「开发者模式」；
3. 点「加载已解压的扩展程序」，选择解压出来的 `nxoptx-chrome-extension` 目录。

**B. 直接用仓库里的源码目录**

直接选本目录（`vms/client/nx_vms_client_desktop/nxoptx-chrome-extension`）即可，省一步解压，
但仓库目录一旦移动或重新 clone，扩展就会失效（报「无法加载」），需要重新选一次目录。

**C. 重新打包**

改完源码后重新生成 zip：

```
python package.py --out <输出路径>.zip
```

> 不建议用 `.crx`：当前 Chrome 只允许从官方商店安装 crx，本地拖入会被拒绝，
> 所以「加载已解压的扩展程序」是自用/内测唯一可靠的方式。另外开发者模式的扩展在每次
> 启动浏览器时会有一次提示，可以忽略。

## 工作原理

扩展从三个来源发现媒体：

1. **网络请求**：`chrome.webRequest` 观察每个标签页的请求，用响应头 `Content-Type`
   和 URL 后缀一起判断类型；
2. **页面 DOM**：内容脚本扫描页面上的 `<video>` / `<audio>` / `<source>`，覆盖那些
   直接从缓存读取、或由脚本动态设置、`webRequest` 看不到的情况；
3. **页面世界**：有些站点把真正的媒体地址放在自己的 JSON 里，既不在 DOM，也不在能读到内容的请求里
   （例如哔哩哔哩）。`bilibili-sniffer.js` 运行在页面自己的 JS 环境（MAIN world）里读取这些数据，
   再把可播的地址通过 `postMessage` 报给内容脚本。

识别出的类型：

| 类型 | 判定 |
| --- | --- |
| `HLS` | URL 以 `.m3u8` / `.m3u` 结尾，或响应头是 mpegurl |
| `DASH` | URL 以 `.mpd` 结尾，或响应头是 `dash+xml` |
| `视频` | `video/*` 或 `.mp4 .m4v .webm .mkv .mov .avi .flv .3gp .ogv` |
| `音频` | `audio/*` 或 `.mp3 .m4a .aac .ogg .oga .opus .flac .wav` |

**URL 后缀优先于响应头**：很多服务器把媒体当作 `application/octet-stream` 返回。

会被**丢弃**的东西：

* 分片文件 `.ts .m4s .cmfv .cmfa .vtt .key .part`——播放器要的是播放列表或容器文件，
  分片只会刷屏；
* `blob:` / `data:` / `mediasource:`（MSE 的内部数据，取不到真实地址）；
* 图片、脚本、JSON 等非媒体响应；
* 重复的同一个 URL（最多保留 300 条，超出时丢弃最早发现的）。

列表是**累计**的：切换页面、关闭标签页都不会清掉已发现的资源，名称（包括手动改过的）
也会保留。整份列表存在 `chrome.storage.local` 里，重启浏览器后仍在；在工具栏弹窗里可以
逐条删除或一键清空。

## 哔哩哔哩

哔哩哔哩默认用 DASH 播放：视频轨和音轨是**两个独立的 `.m4s` 文件**，`<video>` 上只有 `blob:` 地址，
所以按普通的「看请求 / 扫 DOM」思路一个可播地址都拿不到。扩展对它的处理是：

1. 从页面状态里取当前视频的 `bvid` / `cid`（分 P 视频会自动带上分 P 标题）；
2. 调同一个 `playurl` 接口，要求 `fnval=17`：**同时**拿到渐进式 MP4（画面声音一体，可直接播放）
   和 DASH 的高清视频轨 / 音频轨；
3. 条目默认用渐进式地址：账号允许的最高档，登录时最高到 1080P，未登录通常是 720P；
4. 两条高清轨（`videoUrl` / `audioUrl`）和媒体标识（`group`）也一并带给播放器，**只在缓存时使用**；
5. 如果渐进式地址拿不到（会员 / 地区限制等），退回 DASH 视频轨（标注「无音轨」），声音要等缓存合并后才有。

注意：

* 渐进式地址带时效签名，**大约两小时后失效**（地址里的 `deadline` 参数），失效后播放器会报 403；
  重新打开/刷新视频页（或在面板里点「重新扫描」）会拿到新地址，扩展会**自动把播放列表里的旧地址替换掉**，
  名称不变，不需要重新添加；
* **1080P+ / 4K / HDR 只有 DASH 才有**，渐进式封顶 1080P。右键条目选
  「Cache locally (highest quality)」，播放器会下载两条轨、合并成一个本地 MP4，
  之后离线也能播；
* 4K 需要大会员，且不是所有视频都开放；
* 渐进式文件比分片大得多（720P 可能几百 MB）；
* 默认名称是视频标题，画质作为后缀，例如 `标题 720P`；
* 播放依赖账号的 Cookie，所以登录后的画质就是登录后的档位。

## 页面右下角面板

面板**默认关闭**，在工具栏弹窗里勾选「在页面右下角显示提示面板」后才会出现。

* 折叠态是一个小胶囊：「发现 N 个媒体资源」，带脉冲绿点；
* 点开后是卡片，**只显示当前这个页面发现的资源**（工具栏弹窗里的是跨页面的完整列表），
  每条资源可以：
  * **改名字**——改过的名字会保存下来，切换页面也不会丢；名称会作为 `name` 参数传给
    播放器，也就是它在播放器里显示的名字；
  * **添加到播放器** / **复制链接**；
  * 从列表里移除（×）；
* 顶部可以填**目标播放列表**（留空 = 播放器的当前播放列表）；
* 底部有「全部添加」「重新扫描」和「清空」（清空**只清当前页面**的资源）；
* 右上角的 × 会关闭面板，本页不再自动弹出（除非后面又发现了新的资源）。

面板放在 **Shadow DOM** 里，所以网页的样式影响不到它，它也不会污染网页；固定在视口右下角，
不抢占焦点，不阻塞页面点击（胶囊和卡片之外的地方鼠标事件会穿透）。

## 工具栏弹窗

点扩展图标可以看到**所有页面累计的**资源列表，以及设置项：

* **在页面右下角显示提示面板**（默认关；推荐用本弹窗看结果）
* **面板默认展开**
* **目标播放列表**
* **重新扫描当前页面**：等价于页面面板里的「重新扫描」

列表不会随页面切换而清空；每条都可以改名（自动保存）、删除，「清空」会清掉整份列表。
地址栏徽标上的数字是整份列表的条目数。

弹窗开着的时候每秒同步一次后台的结果，所以点完「重新扫描」不用关掉重开。
设置存在 `chrome.storage.sync`，跟随 Chrome 账号同步。

## 重新扫描

面板底部和工具栏弹窗里都有「重新扫描」按钮。点击后：

1. 重新扫描页面 DOM 里的 `<video>` / `<audio>` / `<source>`；
2. 让页面世界脚本（例如哔哩哔哩的）重新查询一次，拿到新的地址；
3. 每个来源**替换**自己上一次的结果，其他来源（例如网络请求）发现的条目不受影响。

这样做是因为流地址往往带**时效签名**：旧地址过一会儿就打不开了，重扫会得到一条新地址，
而不是在列表里多出一条重复项。

## 与播放器的联动

「添加到播放器」会构造出这样一条命令，然后交给浏览器：

```
nxoptx://addStream?url=<URL 编码的流地址>&name=<URL 编码的名称>&playlist=<URL 编码的播放列表>
```

浏览器调用已注册的 `nxoptx://` 处理器，客户端用它转发给**正在运行的**播放器，不会多开窗口。

「全部添加」用的是一条批量命令：

```
nxoptx://addStreams?data=<URL 编码的 base64url 数据>&playlist=<URL 编码的播放列表>
```

其中 `data` 是 `[{"url": "...", "name": "..."}]` 这段 JSON 先做 zlib 压缩、前面加 4 字节大端
未压缩长度，再 base64url 编码的结果。这样做有两个原因：

* 浏览器的外部协议跳转同一时间只能进行一个，逐条跳转会被后一条取消（表现为只有最后一条被添加）；
* 浏览器会**静默拒绝**长度超过约 2 KB 的外部协议 URL，而几条流地址拼成明文 JSON 就已经超过，
  所以必须压缩后再传。

无论单条还是批量：

* 播放器必须正在运行，并且已经注册过 `nxoptx://`（客户端启动时会注册）；
* 名称、URL 全部用 `encodeURIComponent` 编码，空格是 `%20`，和播放器端的
  `QUrlQuery` 解码一致（不是 `+`）；
* 浏览器首次会弹一次「要打开 Desktop Client 吗？」的确认框，勾选「始终允许」即可，之后不再询问。

> 这个确认框是 **Chrome 自己的**，不是扩展画的，它显示在**发起跳转的窗口**里。
> 工具栏弹窗里点「添加到播放器」时，扩展会让**当前标签页**去发起跳转，所以确认框出现在
> 网页窗口里（不会挤在弹窗里）；在页面右下角的卡片里点也是同样的效果。
> 勾过一次「始终允许」之后不再询问。
>
> 注意：Chrome 的「始终允许」是按扩展 ID 记的，而未打包扩展的 ID 由**加载目录**决定。
> 把扩展换到另一个目录重新加载，ID 会变，需要重新勾一次。

## 已知限制

* **MSE / DRM 流**：像 YouTube、Netflix 这类用 `MediaSource` 拼帧、又没有渐进式地址的站点，
  扩展仍然拿不到；哔哩哔哩已经单独支持（见上）。
* **页面全屏播放时面板不可见**：浏览器全屏只渲染全屏元素，这是浏览器的限制；
  退出全屏或用工具栏弹窗即可。
* 分片（`.ts` / `.m4s`）被有意过滤掉了；如果某个站点只暴露分片、没有播放列表，
  列表会是空的。
* 有些站点把流地址放在 iframe 里，而内容脚本只在顶层文档运行，此时用工具栏弹窗仍能看到
  （嗅探是按标签页做的，不受此限制）。

## 文件

| 文件 | 说明 |
| --- | --- |
| `manifest.json` | Manifest V3 清单 |
| `background.js` | Service Worker：嗅探、过滤、去重、徽标、与页面通信 |

| `make_icons.py` | 重新生成 `icons/` 里的图标（需要 Pillow） |
